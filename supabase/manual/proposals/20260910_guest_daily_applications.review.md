# 당일 회차 게스트 신청 변경 검토

사용자의 운영 반영 승인 후 DB, `account-auth`, Firebase Hosting 적용을 완료했습니다.

## 운영 반영 결과

- 연결된 프로젝트와 필수 열을 읽기 전용으로 확인한 후 승인된 SQL만 트랜잭션으로 적용했습니다.
- 이용자 298명, 출입 로그 2,491건, 회차 3개, 회차 신청 8건을 보존했습니다. 기존 신청 내용의 비교 검사도 통과했습니다.
- 적용 SQL SHA-256: `2d7abc0157a1305a4afd1965284c947a70a5543880f43a62ac30b95c4e6f5f2c`.
- 운영에서 현재 이름으로 로그인 후보 조회, 인증 서버 준비 상태, 게스트 함수 및 대체 INSERT 경로의 잘못된 신청자 거부를 확인했습니다. 운영 테스트 레코드는 생성하지 않았습니다.
- `app.schoolchurchimpact.org`와 `sci-center-6f265.web.app`에서 HTML 및 `/assets/index.vOqq06ny.js`가 최종 빌드와 일치함을 확인했습니다.
- 재검증: `node --env-file=.env scripts/verify-guest-daily-production.mjs`, `node scripts/verify-guest-release.mjs`.

## 변경 범위

- 당일 회차 신청 테이블에 추가 신청 답변을 저장하는 `application_answers` 열을 추가합니다.
- 게스트 신청 함수와 동일 검증을 사용하는 직접 INSERT 대체 경로를 추가합니다.
- 기존 이용자·신청·출결·원본 로그를 삭제하거나 초기화하지 않습니다. 기존 회원 신청 권한은 바꾸지 않습니다.
- 게스트 식별은 기존 공개 신청 화면과 동일하게 이름·연락처·생년월일 일치에 기반합니다. 정식 회원 및 관리자 계정 신청에 이 경로를 사용할 수 없습니다. 로그인 권한이나 이용자 조회 권한을 발급하지 않습니다.
- 오늘 열린 회차, 시작 시각 이전, 게스트 허용 여부, 필수 추가 답변을 서버에서 검사합니다. 회차 잠금으로 정원과 대기를 결정하며 재시도로 중복 신청하거나 기존 대기 순번을 바꾸지 않습니다.

## 격리 환경 영향 검사

`node scripts/test-guest-daily-applications.mjs` 통과. 실제 PostgreSQL 엔진(PGlite)에 기존 회차 마이그레이션과 제안 SQL을 적용하여 검증했습니다. 운영 연결이나 운영 데이터는 사용하지 않았습니다.

검증 항목: 익명 권한의 함수 호출 및 직접 INSERT, 신청자 정보 불일치 거부, 정식 회원 거부, 필수 답변, 정원 1명과 대기, 재시도, 게스트 비활성화, 마감, 비회원 명단 조회 차단, 기존 이용자 레코드 보존.

추가 확인: 로컬 서버 모바일 화면에서 생년월일 입력·잘못된 날짜 표시, 게스트 설정 토글, 당일 안내와 신청 버튼, 모의 서버 신청 제출 및 대기 완료 표시를 검증했습니다. 로그인 이름 변경 회귀 테스트와 전체 빌드도 통과했습니다.

## 승인 후 반영 순서와 복구

1. 운영 스키마와 필수 회차 테이블·열의 존재를 읽기 전용으로 확인합니다.
2. 승인된 SQL을 트랜잭션으로 적용합니다. 실패하면 전체 트랜잭션을 롤백합니다.
3. 로그인 검색 서버 변경을 반영하고 새 이름/기존 이름 검색을 확인합니다.
4. 별도 배포 지시 후 Firebase Hosting에 화면 변경을 배포합니다.

문제가 발견되면 프로그램의 게스트 허용을 끄고 새 함수와 INSERT 경로 권한을 회수합니다. 이미 저장된 신청 및 답변 열은 보존하고 삭제하지 않습니다.
