# 반복 프로그램 회차별 신청 전환 검토안

2026-09-11 사용자 승인 후 운영 DB에 적용했다. 기존 신청·출석·로그는 삭제하거나 변경하지 않았다.

적용 전후 모두 회차 3건, 회차 응답 8건으로 동일했다. 미래 회차는 0건이었으며
`(notice_id, session_date)` 고유 제약이 활성화된 상태를 확인했다. 같은 SQL을 먼저
트랜잭션에서 실행하고 롤백한 후 적용했으며, 회원·게스트 함수 모두 미래 회차 허용과
신규 `application_scope=SESSION` 검사를 포함하는 것을 적용 후 다시 확인했다.

## 변경 목적

- 오픈 프로그램의 신청 기능을 제거한다.
- 반복 신청 프로그램은 관리자가 다음 회차를 열 때만 회차 한 건을 만든다.
- 열린 미래 회차도 시작 시각 전까지 신청할 수 있게 한다.
- 기존 `SESSION_RSVP` 오픈 프로그램과 그 회차 기록은 전환 기간 동안 계속 읽는다.

## 적용 전 확인

1. `daily_program_sessions`의 `(notice_id, session_date)` 고유 제약이 유지되는지 확인한다.
2. 기존 회차·응답 건수를 기록한다.
3. 동반 SQL을 dry-run 트랜잭션으로 실행하고 롤백한다.
4. 기존 당일 회차와 신규 미래 회차 각각에 신청·취소 테스트를 한다.

## 영향

- 데이터 삭제 없음.
- 테이블·열 추가 없음.
- 회차 신청 서버 함수의 날짜 제한과 프로그램 유형 검사만 일반화한다.
- 운영 DB 적용 완료. Firebase Hosting 배포는 별도 승인 대상이다.
