# 센터 통계 읽기 연결: 로컬 구현과 남은 연결 작업

기준: `a5315dabb5636875380037c9f2e83ca4a8fb04a7`. 이 변경은 로컬 소스와 합성 테스트뿐이다. OAuth, MCP 서버, 비밀키, 권한, DB 스키마, 배포를 생성하거나 변경하지 않는다.

## 계산 정의

| 지표 | 새 공용 계산 | 기존 화면과의 관계 |
| --- | --- | --- |
| 방문횟수 | KST 사용자·날짜 안에서 퇴실 후 재입실은 새 세션. 유효 공간에서 시작한 방문은 퇴실 누락·0분도 방문으로 집계 | `visitUtils`의 세션 경계를 사용. 이동만 남은 세션도 포함. 자정 넘는 연결은 하지 않음 |
| 순방문자 | 기간 내 유효 방문이 있는 직원 제외 이용자 수, 게스트·미가입 포함 | 웹 통계의 회원 순방문자와 범위가 다르므로 회원/게스트 수도 제공 |
| 공간 방문 | 회원은 양수 측정 구간이 있는 세션·공간 수, 게스트는 세션에서 접촉한 유효 공간 수 | `analyticsUtils.processAnalyticsData` 공간 방문 정의. 공간 이동은 방문횟수보다 공간 방문 수를 크게 만듦 |
| 이용자·날짜 수 | 같은 날 재방문을 합친 수 | 운영 보고서는 이용자·날짜·공간 단위 중복 제거. 기존 Slack `total_visits`는 퇴실·양수 시간이 있는 이용자·날짜 수이므로 그대로 유지 |
| 기록 시간 | MOVE 및 실제 CHECKOUT 사이 공간별 양수 정수 분의 합 | 웹 통계 공간별 측정 시간. 퇴실 없는 마지막 구간은 포함하지 않음 |
| 완료 시간·평균 | 실제 퇴실한 유효 세션의 측정 분 합 / 그 세션 수 | 0분 세션 제외, 평균 분모를 함께 제공. 보고서의 이용자·날짜 분모 평균과 구분 |
| 퇴실 누락 추정 | 당일 현재 또는 지난 날짜 KST 22시까지 최초 입실부터 추정, 별도 표시 | 실측 시간에 더하지 않음. 품질 참고값이며 실제 퇴실 시간이라는 뜻이 아님 |
| 신청·대기·취소 | 각 프로그램/회차의 현재 JOIN/WAITLIST/CANCELLED 레코드 수 | 신청 이벤트 누적 횟수가 아님. 회차로 전환된 프로그램은 기존 전체 신청을 중복 합산하지 않음 |
| 참석 | JOIN이고 참석 표시가 있는 현재 응답, 개방형은 날짜별 출석 | 취소 응답에 남은 참석 표시 제외. 직원 admin/master 및 is_staff 제외. 폐기·취소 회차 제외 |

일·월, 월요일 시작 주, 바로 이전 같은 단위 기간 비교를 지원한다. 시작 포함·끝 제외 KST 경계다. 현재 주/월의 미래 일정 신청은 포함하되 미래 참석은 집계하지 않는다. 로그는 계산 시점 이후 제외한다. 신청 취소 시점별 이력 분석, 자정 넘는 체류 연결은 현재 구현 범위 밖이다.

웹 정의 근거: `src/utils/visitUtils.js`, `src/utils/analyticsUtils.js`, `src/utils/operationProgramStats.js`, `src/utils/responseState.js`, `src/api/programSessionsApi.js`. 웹 `미가입` 처리에는 화면별 차이가 있어 공용 엔진은 게스트로 명시한다. 기존 웹앱 코드는 바꾸지 않았다.

## 서버 읽기·출력 경계

`source.mjs`는 users(id,user_group), staff_directory(id,role), locations(id), logs(집계용 이벤트), notices(집계용 일정/상태), notice_responses, daily_program_sessions, daily_program_session_responses, open_program_attendance의 고정 9개 계획만 제공한다. 요청에서 테이블·필드·SQL·회원 필터를 받지 않는다. 사용자 ID는 직원 제외와 중복 제거에 내부적으로만 쓰며 반환하지 않는다. 이름, 학교, 생년월일, 원문 피드백, 개인별 로그는 선택하지 않는다. 새 RPC는 없다.

외부 연결용 소스 어댑터는 500행 키셋 페이지, 안정된 복합 정렬, 모든 페이지 완료 증거와 동일 조회 기준시점을 구현해야 한다. 100,000행 상한은 자원 제한이며 초과 시 실패한다. 충돌 중복·진행 없는 페이지·오류는 `source_incomplete`, 실제 빈 조회는 0과 평균 null이다. 여러 REST 읽기의 동시 변경 일관성은 아직 증명되지 않았으므로 실제 어댑터를 구현·검증하기 전 연결하지 않는다.

`boundary.mjs`는 인증 및 공개 승인 함수가 없는 기본 상태에서 차단한다. 검증된 서버 사용자, 활성 세션, 정확한 허용 subject, `center:statistics:read` 범위를 매 호출 확인한다. 요청의 가짜 verified/subject 헤더를 신뢰하는 구현은 금지한다. 기존 account-auth가 OAuth 서버라는 가정은 하지 않는다. 인증은 주입 계약뿐이며 실제 OAuth 발급/연결은 구현하지 않았다.

`publication.mjs`는 계산과 별개다. 검토된 서버 정책의 기간·지표·breakdown 허용 목록, 명시적 exact 허용, 최소 기여자/셀, 이용시간 최대 기여 비중을 적용한다. 미결정 값은 review_required. 전 지표에 20명·완료월 조건을 적용하지 않는다. 테스트의 0명/0셀 허용은 합성 fixture 설정이며 운영 권장값이나 개인정보 안전성 인증이 아니다.

프로그램 정보는 DB 원문을 그대로 투영하지 않는다. 검토된 서버 catalog의 published+approved 항목에서 title, description, audience, schedule, location, capacity, recruitment_status만 허용한다. 프로그램/회차는 검토된 별칭으로 반환한다. 메일·전화·제어문자·마크업 탐지는 추가 방어이며 사람 이름·희귀 상황 등 모든 개인정보를 제거하는 익명화가 아니다. 게시 사실만으로 안전하다고 판단하지 말고 프로그램 담당자의 필드별 검토를 거친 catalog를 공급해야 한다. 검토되지 않은 description은 제공하지 않는다.

## 실제 공개 정책을 정할 때

1. Jin 본인 전용 센터 전체 일·주·월 카운트부터 상황별 검토 후 정확 값 허용 여부를 결정한다. 직원과 게스트 포함 범위를 UI에 표시한다.
2. 프로그램/회차별 소수 인원, 희귀 대상·일정·장소 조합은 별도 검토한다. 작은 셀 하나를 숨겨도 전체에서 뺄 수 있으므로 현재는 breakdown 전체를 보류한다. 전체 지표까지 기계적으로 모두 보류하는 규칙은 아니다.
3. 총 이용시간과 유효 세션 수는 평균을 복원한다. 평균만 숨기는 것으로 충분하지 않으며 기여자 수·한 사람의 기여 비중·시간 반올림/구간화 등 묶음 공개를 검토한다. 현 엔진은 정확값을 계산하고 정책 승인 전 반환하지 않는다.
4. 같은 기간 반복, 현재 기간 새로고침, 일/주/월 중첩, 이전 기간 비교는 차분으로 작은 집단을 드러낼 수 있다. `authorizeRelease`가 모든 호출·동시 호출의 공개 이력을 함께 판단해야 한다. 단일 프로세스 메모리 guard는 운영 안전성을 보장하지 않는다. 기존 이용 가능한 저장/감사 수단으로 판단 계약을 구현하며 별도 관리자·스냅샷 시스템을 필수로 추가하지 않는다. 적절한 수단이 없으면 공개 보류다.

## Slack 호환

`slack-tsf/index.ts`의 getVisitMetrics/getProgramMetrics는 `slack.mjs`를 거쳐 같은 계산 함수를 호출하고 `statistics_v2`를 추가한다. 방문·순방문자·체류시간은 방문 경로 하나에 포함된다. 기존 summary/groups/programs, 피드백 상세 기능, Slack 인증·이벤트 처리, Notion/공지 쓰기는 유지한다. 기존 개인 피드백은 이 새 외부 경계에 연결하지 않는다.

기존 Slack의 offset REST 페이지 방식과 상한은 유지되어 동시 업데이트 일관성 보장은 없다. 새 필드는 기존 소스 상한 도달/새 조회 실패 시 incomplete로 표시한다. 회차 통계를 위해 전체 신청/직원/회차/회차응답/개방형출석 최소 필드 읽기가 추가되어 비용이 늘어난다. 새 회차 통계는 프로그램 최초 날짜가 아닌 해당 회차 날짜를 기준으로 기간을 적용한다. 기존 프로그램 목록의 날짜 필터는 유지한다. 안정 정렬을 넣었지만 스냅샷과 같은 의미는 아니다. 운영 검증 전 배포하지 않는다. 응답 없는 프로그램/피드백 사용자의 빈 결과 객체 형태도 보완했다.

## 검사·연결·롤백 순서

- 합성 fixture로 KST 경계, 재방문, MOVE, 직원 제외, 퇴실 누락, 중복 충돌, 회차 전환/취소/출석, 1501행 페이지, 소스 실패 vs 0, 메타데이터 방어, allowlist, 위조 인증, 반복 공개 guard, 이전 기간 비교를 검사한다.
- 실제 Slack 함수 몸체를 오프라인 mock으로 실행하여 공유 계산과 일치하고 기존 응답이 유지되는지 확인한다. 기존 웹 세션 경계도 비교한다. baseline 전체를 실행한다.
- 후속 승인 후 기존 Supabase 환경에 전용 HTTPS MCP 읽기 경로와 실제 OAuth 연계를 구현한다. 연결 UI가 요구하는 인증 프로토콜을 먼저 확인하고 audience/issuer/expiry/revocation 등 서버 검증을 테스트한다. 새 키/권한은 이번 변경에 없다.
- 서비스 계정은 서버 내부에만 둔다. 학생 데이터/실제 로그를 모델에 보내지 않는 출력 경계와 운영 동시 변경/페이지 완전성을 검증한다. 명시적 배포 승인 후 Edge Function 대상만 배포한다. 웹 변경·Firebase 배포는 이 기능에 필요 없다.
- 롤백은 이전 Slack 함수 버전 재배포와 새 읽기 경로 비활성화. DB 데이터나 스키마를 되돌릴 필요가 없다. 이번 로컬 파일은 아직 push/deploy하지 않는다.
