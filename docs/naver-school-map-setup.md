# 학교 지도 설정

학교 관리 → 지도 보기에서 학교명 검색과 독립적인 강동·강서·센터 미지정 필터를 조합할 수 있습니다. 일반 학교 목록의 단일 지역 필터는 지도에서 중복 적용하지 않습니다.
학교 핀·학교 히트맵·학생 히트맵을 전환합니다. 학교 히트맵은 위치가 연결된 등록 학교당 한 점, 학생 히트맵은 청소년 수를 가중치로 사용하며 졸업생은 제외합니다.
지도는 처음 열 때만 등록 학교 전체 범위를 맞춥니다. 팝업 열기·닫기와 필터·표시 방식 변경은 현재 중심과 확대 수준을 유지합니다. ‘전체 학교 보기’를 누르면 현재 조건의 학교 범위로 이동합니다.

핀 색상은 학교의 관리 센터 기준입니다. 강동은 빨강, 강서는 파랑, 센터 미지정은 회색입니다.
기존 학교 목록과 동일하게 `manager_ids`에 담당자가 지정된 학교를 연결 학교로 표시합니다.
연결 학교는 채운 핀, 미연결 학교는 흰 바탕 테두리 핀으로 구분합니다.
‘전체 / 연결 / 미연결’ 필터는 학교 목록, 핀, 밀도 계산에 함께 적용되며 기존 검색·지역 필터와 조합됩니다.
핀 제목과 목록에도 연결 상태와 청소년 수를 표시합니다. 히트맵의 색상은 센터 구분이 아니라 현재 조건 내 상대적인 청소년 밀도를 의미합니다.
학생 히트맵은 회원 구분이 `청소년`인 회원만 집계하고 `졸업생`·직원·게스트는 제외합니다. 0명인 학교는 학생 히트맵에서 제외하며 학교 히트맵에는 포함합니다.
같은 좌표에 있는 학교는 인원을 합산한 뒤 네이버 WeightedLocation으로 전달하며, 가까운 학교의 영향은 겹칠 수 있습니다.
학교별 인원과 위치가 없어 지도에서 제외된 인원을 화면에 표시합니다. 학교 연결은 school_id를 우선하고, 이름만 있는 경우 기존 학교명 정규화 규칙을 사용합니다.

## 센터 위치

하이픈(서울 강동구 양재대로 1592)과 이높플레이스(서울 동작구 여의대방로 206-1, 크리스탈빌딩 6층)는 이름표가 붙은 건물 아이콘으로 표시합니다.
네이버 주소 검색으로 확인한 좌표는 `src/utils/mapCenters.js`에서 관리하며, 각각 강동·강서 필터에 따라 표시합니다. 학교 연결·검색 필터와 무관하게 모든 지도 모드에서 보이고, 누르면 주소를 확인할 수 있습니다. 센터는 학교·학생 집계와 히트맵에 포함하지 않습니다.

## 미등록 학교 표시

기본은 꺼져 있습니다. 켜면 현재 지도 영역의 운영 중인 학교를 채운 회색 원으로 보여주며, 원을 누르면 이름과 주소를 확인할 수 있습니다.
자료는 한국교육시설안전원의 [전국초중등학교위치표준데이터](https://www.data.go.kr/data/15021148/standard.do)이며 2026-10-01 기준 운영 학교 12,004곳을 포함합니다.
`public/data/public-school-locations.json`은 표시를 켰을 때만 불러옵니다. 주소별 네이버 좌표 검색은 실행하지 않습니다.
갱신 명령은 `node scripts/refresh-public-school-map.mjs`입니다. 공개 다운로드 항목과 전체 건수·좌표·학교 ID 중복을 검증한 후 파일을 교체합니다.
‘중학교·고등학교’가 기본 선택이며 초등학교도 켤 수 있습니다. 확대 수준이 10보다 낮거나 현재 영역의 후보가 300곳을 넘으면 확대 안내를 보여주고, 충분히 확대하면 표시합니다.
등록 학교는 현재 센터·연결·검색 필터와 무관하게 전체 학교 목록을 기준으로 제외합니다. 학교명 정규화와 확인된 약칭, 좌표 인접 여부를 함께 사용해 다른 지역의 동명 학교가 잘못 제외되지 않도록 합니다.
미등록 학교에는 관리 센터를 추정 배정하지 않습니다. 센터·연결 필터는 등록 학교에 적용하며, 미등록 학교는 현재 지도 영역·학교명 검색·학교급을 따릅니다.
미등록 학교를 schools 테이블에 추가하지 않으며 학교·학생 히트맵과 청소년 집계에도 포함하지 않습니다. 공개 자료의 갱신 시점 때문에 신설·이전 학교 정보가 현황과 다를 수 있습니다.

## 네이버 클라우드 설정

1. https://console.ncloud.com/ 에 로그인합니다.
2. 서비스 검색에서 Maps를 찾아 Application에서 애플리케이션을 등록합니다.
3. Web Dynamic Map(지도 표시), Geocoding(주소 검색)을 선택합니다.
4. Web 서비스 URL에 로컬 개발 주소 `http://localhost:5173` 및 사용할 실제 웹앱 도메인을 등록합니다. 도메인 입력 규칙은 콘솔의 안내를 따릅니다.
5. 등록한 애플리케이션의 인증 정보에서 Client ID를 복사합니다.
6. 프로젝트의 `.env.local`에 아래 값을 추가합니다. Client Secret은 넣지 않습니다.

```dotenv
VITE_NAVER_MAPS_CLIENT_ID=발급받은_Client_ID
```

개발 서버를 다시 시작하면 적용됩니다. 배포 시에는 이 환경 변수를 설정한 상태로 다시 빌드해야 합니다.
실제 서비스 반영은 사용자의 명시적 배포 요청 후 진행합니다.

공식 문서:
- https://guide.ncloud-docs.com/docs/en/maps-app
- https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html

## 학교 위치 연결

학교별 ‘위치 연결’에서 정확한 학교 도로명주소를 검색하고, 결과를 확인한 후 ‘이 주소로 저장’을 누릅니다.
학교명만으로 위치를 추측하지 않습니다. 저장 권한은 기존 학교 수정 권한을 따릅니다.
학생 소속에만 있고 정식 학교 레코드가 없는 학교는 먼저 학교 목록에 등록해야 합니다.

주소·위도·경도는 Supabase의 `schools.map_address`, `schools.map_latitude`, `schools.map_longitude`에 공유 저장됩니다.
브라우저 로컬 저장소는 사용하지 않습니다. 로컬 화면에서도 실제 저장을 누르면 같은 Supabase 프로젝트에 반영됩니다.
위치가 없는 학교는 목록에 남지만 지도와 밀도 계산에서 제외됩니다.
이 지도는 웹앱에 등록된 학교의 분포를 보여주며, 관리 여부·활동량을 별도로 판정하지 않습니다.

## 마이그레이션과 복구

`20261015090000_school_map_locations.sql`은 기존 데이터를 수정하지 않고 3개 nullable 항목과 좌표 검사만 추가합니다.
로컬 스키마 검증: `node scripts/test-school-map-migration.mjs`
운영 반영 도구: `node scripts/apply-school-map-migration.mjs --inspect|--dry-run|--apply`
연결 대상은 기존 프로젝트 `erecqalsxoxrufggvmcc`로 고정되어 있습니다.

문제가 발생하면 이전 프런트엔드로 복구해도 기존 학교 기능은 계속 동작합니다.
추가 항목은 그대로 보존해 위치 데이터 손실을 피합니다. 이번 마이그레이션에는 기존 학교·활동 기록 삭제나 권한 변경이 없습니다.
