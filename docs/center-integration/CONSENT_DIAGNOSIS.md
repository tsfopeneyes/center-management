# 재연결 오류 확인 기록

2026-10-07: 사용자가 새 앱 연결에서 계속 일반적인 유효하지 않은 요청 메시지를 보고함.

- 해당 요청의 네이티브 승인 상태는 approved였고, 조회 당시 만료되지 않았으며 클라이언트·사용자·리소스·콜백·PKCE가 예상 설정과 일치했다.
- 로컬 consent_requests 행은 생성되었지만 completed_at은 비어 있었다. 기존 연결은 active이고 이전 authorization을 유지했다.
- 실제 운영 역할로 해당 요청의 활성화 UPDATE와 완료 표시를 실행한 뒤 ROLLBACK하는 검사는 성공했다. 운영 상태는 보존했다.
- 확인용 브라우저에는 웹앱 로그인 세션이 없어 사용자의 실패 HTTP 응답은 재현하지 못했다. 전체 연결이 해결됐다고 간주하지 않는다.
- 프런트엔드가 모든 실패를 같은 메시지로 숨기던 문제를 수정했다. 요청 확인/연결 준비/승인/활성화 단계와 제한된 오류 코드·HTTP 상태만 표시한다. 원문 오류, 토큰, 콜백 주소는 표시하지 않는다.
- 웹 검사 9개 통과. 실제 실패 단계 확인 후 그 원인을 수정해야 한다. 앱 삭제/재생성이나 동일 새로고침 반복으로 해결됐다고 주장하지 않는다.

추가 확인: 사용자가 보낸 새 요청도 completed=true, active=true, same_authorization=true였지만 화면은 요청 확인 validation_failed/400을 표시했다. AuthProvider는 검증된 세션을 갱신할 때 authenticated → refreshing → authenticated로 상태를 전환한다. 기존 consent effect가 이 변화를 구독해 활성화 후 복귀를 취소하고 단일 사용 요청을 다시 조회할 수 있었다. effect 의존성을 검증된 사용자/프로필 식별자로 변경해 갱신 중에는 유지하고, 계정 변경·차단·로그아웃에는 취소한다. 서버의 세션·권한 검증은 그대로 유지한다. OAuth 화면에서 서비스워커 교체에 의한 자동 새로고침도 억제한다. 웹 검사 10개 통과. 새 앱의 ChatGPT 콜백 완료 여부는 별도 확인이 필요하다.
